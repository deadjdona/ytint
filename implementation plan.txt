# YouTube Comment Corpus - Comprehensive Implementation Plan

This plan maps the 14 sections of `description_long.md` into a structured data pipeline, organizing the analytical goals into distinct, sequential stages.

## Pipeline Architecture

### ✅ Stage 1: Data Enrichment (`s01_enrich.py`)
**Goal:** Compute raw comment-level and thread-level features across the corpus.
- ✅ **Temporal (Sec 1):** Compute `reply_latency`, `time_since_upload`, and `is_thread_terminal` flag.
- ✅ **Linguistic (Sec 4):** Detect language (`fastText`/`langdetect`), calculate readability (`textstat`), count emojis/all-caps ratios, and extract hashtags/mentions via regex.
- ✅ **Sentiment & Affect (Sec 3):** Calculate continuous valence (VADER / XLM-R), emotion categories (GoEmotions), and toxicity/profanity scores (Perspective API/Detoxify).
- ✅ **Cross-Modal (Sec 12):** Extract video timestamp mentions via regex to map comments to video timelines.
- ✅ 🛡️ **Bullet-Proofing & Robustness:** Implement chunked/streaming I/O (`polars` or `dask`) to handle massive data files. Drop or impute null timestamps. **Pitfall Addressed:** Convert all UTC timestamps to local timezone based on channel geography *before* any diurnal binning to prevent cyclic smearing.

### ✅ Stage 2: Network & Graph Construction (`s02_network.py`)
**Goal:** Build, analyze, and extract structural metrics from reply threads and user interactions.
- ✅ **Thread Structure (Sec 8):** Calculate reply chain maximum depth, width, and branching factor. Track initiator vs. response patterns.
- ✅ **Graph Generation (Sec 5):** Use `networkx` to build Reply-tree forests, Author-Video bipartite graphs, and Co-commenting (Jaccard overlap) graphs.
- ✅ **Graph Metrics (Sec 5):** Compute PageRank, In-degree centrality, community detection (Louvain/Infomap), and K-core decomposition.
- ✅ 🛡️ **Bullet-Proofing & Robustness:** Implement graph size limits; automatically switch from `networkx` to `igraph` or `graph-tool` if node count exceeds 100k to prevent OOM errors. Isolate and prune orphan nodes before running expensive centrality algorithms.

### ✅ Stage 3: Topic & Semantic Modeling (`s03_semantics.py`)
**Goal:** Extract topics, calculate semantic embeddings, and assess semantic drift.
- ✅ **Topic Modeling (Sec 2):** Run BERTopic or LDA over the corpus to generate topic assignments and probabilities per comment.
- ✅ **Embeddings (Sec 2):** Compute sentence embeddings (`all-MiniLM-L6-v2`) and reduce to 2D/3D spaces using UMAP/t-SNE for clustering.
- ✅ **Intent Taxonomy (Sec 2):** Apply zero-shot classification (`facebook/bart-large-mnli`) to categorize root comment intents (praise, complaint, spam, etc.).
- ✅ **Drift & Keywords:** Calculate TF-IDF per category and track semantic drift using Procrustes aligned Word2Vec models.
- ✅ 🛡️ **Bullet-Proofing & Robustness:** Cache embeddings to disk (FAISS or `.npy` arrays) to ensure idempotency and save compute time on re-runs. **Pitfall Addressed:** Extremely short comments (e.g. "<3", "first") create sparse matrices breaking LDA; aggregate short comments by thread or fallback to Biterm Topic Model (BTM).

### ✅ Stage 4: Aggregation & Cohort Modeling (`s04_aggregation.py`)
**Goal:** Aggregate comment-level data to Video and Author levels, establishing cohorts.
- ✅ **Author Identity (Sec 11):** Calculate power-law activity (Zipf), footprint users across channels, and track display name reuse.
- ✅ **Cohorts (Sec 6):** Compute RFM segments (Champions, Loyal, At Risk), fan loyalty (single vs multi-channel), and construct behavioral K-means cohorts.
- ✅ **Attention Dynamics (Sec 1, Sec 7):** Fit exponential decay curves for comment velocity per video (calculating "half-life"). Compute Gini coefficients and top-K concentration for like-counts.
- ✅ **Narrative Trends (Sec 1):** Apply Savitzky-Golay filters to comment volume time-series to detect $>3\sigma$ revival spikes.
- ✅ 🛡️ **Bullet-Proofing & Robustness:** Handle right-censored data (recent videos will mathematically skew decay fits). Use robust scaling (Median/IQR) instead of Mean/Standard Deviation, as engagement metrics follow extreme power-law (Zipf) distributions that will break K-means.

### ✅ Stage 5: Advanced Statistical & Predictive Modeling (`s05_modeling.py`)
**Goal:** Run anomaly detection, causal analysis, and machine learning predictions.
- ✅ **Temporal Analysis (Sec 1):** Apply STL Decomposition for weekly/diurnal heatmaps, and Kaplan-Meier estimation (via `lifelines`) for thread survival/death.
- ✅ **Anomaly & Spam (Sec 10):** Run Isolation Forest/DBSCAN for bot detection, SimHash for near-duplicate spam discovery, and track Poisson bursts for brigading.
- ✅ **Predictive (Sec 13):** Train XGBoost/LightGBM models to predict like-counts (using SHAP for feature attribution) and use ARIMA/Prophet for engagement forecasting.
- ✅ **Comparative Analysis (Sec 9):** Run Kruskal-Wallis + Dunn's test for category benchmarking, and CausalImpact for before/after event analysis.
- ✅ 🛡️ **Bullet-Proofing & Robustness:** Ensure train/test temporal splits avoid future-leakage in XGBoost. **Pitfall Addressed:** Handle severe class imbalance in toxicity/spam detection by implementing SMOTE or sample-weighting in the loss function to prevent the model from defaulting to the majority class.

### ✅ Stage 6: Visualizations & Reporting (`s06_visualize.py`)
**Goal:** Generate the required visual outputs proposed in `description_long.md` (using matplotlib, seaborn, plotly, etc.).
- ✅ **Temporal:** Kaplan-Meier survival step-plots, 24x7 matrix heatmaps, and decay fit line charts.
- ✅ **Semantics:** pyLDAvis interactive MDS scatters, UMAP scatter projections, entity frequency tree maps.
- ✅ **Sentiment:** Joyplots/ridge plots of valence, Plutchik emotion wheels, and diverging bar charts for sentiment shifts.
- ✅ **Graph:** Force-directed network layouts, chord diagrams for user overlap, and bow-tie schematic flow diagrams.
- ✅ **Metrics/Cohorts:** Pareto charts, RFM 3D scatters, cohort retention heatmaps, and SHAP beeswarm plots.
- ✅ 🛡️ **Bullet-Proofing & Robustness:** Dynamically scale visualization strategies. If $N > 10,000$ points on a scatter/network plot, automatically switch to `datashader` or hexbins to prevent browser crashes and visual overplotting blocks.
